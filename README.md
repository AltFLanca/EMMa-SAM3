
# EMMa-SAM3

Generate foreground masks from EMMa product images using [SAM3](https://github.com/facebookresearch/sam3), a text-prompted segmentation model. Currently, only the first product image associated with each ASIN is processed.

For each product image, the segmentation pipeline follows three stages:

1. **Product title** - Attempts segmentation using the full product title as the text prompt.
2. **Product category** - If no detection is found, retries using the most specific product category.
3. **Thresholding fallback** - If neither prompt produces a detection, generates a mask using grayscale inverse thresholding followed by morphological opening.

When SAM3 detects multiple instances, their predicted masks are combined into a single foreground mask.

Dataset access and augmentation storage are handled through [EMMa-Wrapper](https://github.com/AltFLanca/EMMa-Wrapper).

## Setup

Install the project dependencies using [uv](https://docs.astral.sh/uv/). From the repository root, run:

```bash
uv sync --locked
```

A prepared EMMa dataset is required. The dataset and SAM3 model weights are not included in this repository.

## Repository Structure

- `src/test_single.ipynb` - Notebook for testing individual samples.
- `src/test_inference.ipynb` - Notebook for testing batched inference.
- `src/inference.py` - Generates foreground masks using SAM3 with a thresholding fallback.
- `src/valid_output_filtering.py` - Produces a list of valid ASINs from the generated augmentations.
- `src/visualize_augmentation_output.ipynb` - Visualizes generated masks for inspection.

## Generate Augmentations

Mask generation requires an `.npy` file containing the ASINs to process, provided through the `--asins` argument, and a local SAM3 model directory, provided through `--sam3-root`.

The segmentation and thresholding fallback operations can be configured using the following arguments:

- `--segmentation-threshold` - Minimum SAM3 detection confidence score.
- `--mask-threshold` - Threshold used to binarize predicted segmentation masks.
- `--image-size` - Image size used by the SAM3 processor.
- `--thresholding-threshold` - Grayscale threshold used for inverse binary thresholding.
- `--thresholding-kernel-size` - Kernel size used for morphological opening.
- `--thresholding-open-iterations` - Number of morphological opening iterations.

Run inference with:

```bash
uv run src/inference.py \
  --dataset-root /path/to/EMMa \
  --asins /path/to/augmented_asins.npy \
  --output /path/to/EMMa-SAM3/masks.h5 \
  --sam3-root /path/to/models/facebook/sam3 \
  --segmentation-threshold 0.25 \
  --mask-threshold 0.5 \
  --image-size 560 \
  --thresholding-threshold 253 \
  --thresholding-kernel-size 3 \
  --thresholding-open-iterations 2
```

Generated masks are stored in an HDF5 file at the specified output path, with one finalized binary mask per ASIN. A corresponding `masks.h5.counts.json` file tracks the number of masks generated by each segmentation stage.

To inspect the generated masks, use [visualize_augmentation_output.ipynb](src/visualize_augmentation_output.ipynb).

**Note:** Inference automatically skips ASINs already present in the output file. When changing models or inference settings, use a new output path to avoid mixing results generated with different configurations.

## Validate Augmentations

The [valid_output_filtering.py](src/valid_output_filtering.py) script processes the generated augmentations and produces a `valid_asins.npy` file in the same directory as the input HDF5 file.

Run validation with:

```bash
uv run src/valid_output_filtering.py \
  --dataset-root /path/to/EMMa \
  --augmentation-file /path/to/EMMa-SAM3/masks.h5
```

Because the output is always named `valid_asins.npy`, validating multiple HDF5 files in the same directory overwrites the previous list.

**Note:** The current implementation does not apply any additional filtering criteria. All processed ASINs with stored masks are considered valid.
